# 踩坑：应用内「添加到桌面」失败，系统小组件选择器却能加

| 项目 | 内容 |
|---|---|
| 现象 | 「我的 → 小组件 → 添加到桌面」失败，提示「没有检测到新添加的小组件」；系统桌面的小组件选择器里拖出同一个组件正常 |
| 日期 | 2026-11-09 |
| 环境 | Redmi K40（alioth，HyperOS / Android 15，targetSdk 35），MIUI 桌面 `com.miui.home`，真机无线调试 |
| 结论 | 小米桌面处理 `requestPinAppWidget` 时先查本应用的 MIUI AppOp `INSTALL_SHORTCUT`（op 10017）；未开启「桌面快捷方式」时直接放弃，且只短暂拉起 `AddItemActivity` 就退出，导致 App 把这次失败误判成「用户取消」 |

---

## 一、复现与实锤

从「我的 → 小组件」点「添加到桌面」，在小米桌面上的完整链路（logcat）：

```
W/XSpaceManagerServiceImpl: checkXSpaceControl, from:android, to:com.miui.home,
        with act:android.content.pm.action.CONFIRM_PIN_APPWIDGET
I/ActivityTaskManager: START u0 {act=android.content.pm.action.CONFIRM_PIN_APPWIDGET
        cmp=com.miui.home/.launcher.AddItemActivity} from uid 1000
D/AddItemActivity-PinShortcutRequestUtils: mRequest=2
E/AddItemActivity-PinShortcutRequestUtils: add widget failed,
        com.cherry.wakeupschedule has no permission
```

关键点：

- `AppWidgetManager.requestPinAppWidget()` 返回 `true`（桌面确实「声称支持」），请求也被系统转给了小米桌面；
- 小米桌面的 `AddItemActivity` 在权限检查这一步直接 `return`，**不加组件、不弹确认框**；
- `AddItemActivity` 启动又立刻结束，App 页面收到一次 `onPause → onResume`，`WidgetCenterActivity` 因此把 `leftForeground` 记为 true；
- 老逻辑把「离开过前台 + 组件数没变多」判成 `CANCELED`，于是只弹一句温和提示，用户既没看到确认框，也拿不到「桌面快捷方式」的引导。

同一次操作里，`dumpsys appwidget` 的组件数不变；把权限开关打开后重试，组件数立刻 +1，且**全程没有任何确认框**。

## 二、权限到底卡在哪一层

反编译小米桌面（`/product/priv-app/MiuiHomeT/MiuiHomeT.apk`）后可见：

```smali
# AddItemActivity.lambda$setupWidget$2$AddItemActivity
invoke-static {v11, v0},
    Lcom/miui/home/launcher/common/Utilities;.hasAddShortcutPermission:(Landroid/content/Context;Ljava/lang/String;)Z
...
const-string v1, "add widget failed, "
const-string v12, " has no permission"
invoke-static {v2, v11}, Landroid/util/Log;.e:(Ljava/lang/String;Ljava/lang/String;)I

# Utilities.hasAddShortcutPermission
sget v2, Lcom/miui/home/launcher/common/MiuiResource$AppOps;.OP_INSTALL_SHORTCUT:I
invoke-static {v3, v2, v1, v4},
    Lcom/miui/launcher/utils/AppOpsManagerUtils;.noteOpNoThrow:(Landroid/content/Context;IILjava/lang/String;)I
if-nez v3, :allowed   # 0 == MODE_ALLOWED
```

而 `MiuiResource$AppOps.<clinit>` 里：

```smali
# SDK >= 24
const/16 v0, #int 10017
sput v0, Lcom/miui/home/launcher/common/MiuiResource$AppOps;.OP_INSTALL_SHORTCUT:I
```

即判定依据是 **MIUI 自定义 AppOp 10017**，不是 `requestPinAppWidget` 的返回值。

### 声明 `INSTALL_SHORTCUT` 权限没有用

实测（同一台机器）：

| 操作 | op 10017 | 结果 |
|---|---|---|
| 原始安装（Manifest 未声明） | `ignore` | 失败，`has no permission` |
| 在 Manifest 加 `com.android.launcher.permission.INSTALL_SHORTCUT`（已 granted） | 仍 `ignore` | 仍然失败 |
| 设置 → 应用管理 → 权限管理 → 其他权限 → 桌面快捷方式 → **始终允许** | 默认放行 | 成功，无确认框 |

两个注意点：

- 这台 ROM 的 `android.Manifest.permission.INSTALL_SHORTCUT` 字面量就是 `com.android.launcher.permission.INSTALL_SHORTCUT`（framework `Manifest$permission` 字段值可证），且它是普通权限，安装即授予——但对 op 10017 的默认值没有影响；
- 该开关对第三方应用默认是「拒绝」，微信之类能用的应用是多带了一步用户手动放行。`appops get <pkg> 10017` 可直接查看当前状态。

## 三、修复

1. **提前探测，直接申请**：`WidgetPinSupport.shortcutPermissionDenied()` 通过反射调用
   `AppOpsManager.checkOpNoThrow(10017, uid, pkg)`（hiddenapi 标记为 UNSUPPORTED，不拦截）。
   点「添加到桌面」时先查开关：
   - 已关闭 → 不发起必然失败的请求，直接弹「需要「桌面快捷方式」权限」，主按钮「去开启权限」；
   - 已允许 / 查不到 → 按原流程发起 `requestPinAppWidget`。
   反射失败一律返回 `null`（fail-open），不会因为探测失败拦下添加。
2. **开启后自动继续**：点「去开启权限」时记下待添加的组件，跳到
   `com.miui.securitycenter/com.miui.permcenter.permissions.PermissionsEditorActivity`
   （打不开回落到应用详情页）；用户回到本页时 `onResume` 再查一次，已允许就直接续上那次添加，
   不用再点一遍「添加到桌面」。
3. **纠正误判**：`WidgetPinPolicy.evaluate` 新增 `desktopRejectsSilently`。若探测不可用、
   仍走到「发请求后核验」的老路径，小米/红米/POCO 上失败时 `AddItemActivity` 只闪一下，
   `leftForeground` 不能当成「用户取消」，一律返回 `NO_RESPONSE`，走带权限入口的引导。
4. **提示文案**：机型提示排到手动步骤之前，并写明「始终允许」这一步。

代码位置：

- `widget/WidgetPinPolicy.kt`：判定语义（纯 JVM，单测覆盖）
- `widget/WidgetPinSupport.kt`：机型识别、op 探测、权限页 Intent、文案
- `WidgetCenterActivity.kt`：预检、权限申请、回来自动继续、失败引导

## 四、验证

```bash
# 单元测试
./gradlew :app:testDebugUnitTest --tests "com.cherry.wakeupschedule.widget.WidgetPinPolicyTest"

# 真机：关掉开关 → 点添加 → 应立即弹「需要「桌面快捷方式」权限」（不等 3 秒核验）
adb shell appops set <pkg> 10017 ignore
# 点「去开启权限」→ 设置 → 应用管理 → 本应用 → 权限管理 → 其他权限 → 桌面快捷方式 → 始终允许
# 直接返回（不用再点添加）→ onResume 自动续上，组件落到桌面，状态行变「已添加 N 个」
```

`dumpsys appwidget` 的 `Widgets:` 段可核对组件数变化；`logcat | grep AddItemActivity-PinShortcutRequestUtils` 可确认是否还出现 `has no permission`。

> 注意：MIUI 的权限页状态与实际 op 可能暂时不同步（例如先用 `appops set` 改了 op，
> 权限页仍显示上一次的选择）。复现时以 `appops get <pkg> 10017` 为准，或先在权限页
> 切到「拒绝」再切回「始终允许」，让 MIUI 自己写一次。
