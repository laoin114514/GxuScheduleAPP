# 西大课栈 · 动效优化方案

> 目标：解决「动效单调」——把当前只有「按压反馈 + 少数弹层」的零散动画，
> 升级成一套覆盖**页面转场 / 列表入场 / 状态切换 / 弹层交互 / 加载反馈**的统一动效语言，
> 让 App 用起来「顺手、跟手、有回应」，同时不牺牲性能与可访问性。
>
> 状态：方案设计 + 首批落地（工作区内实现，未提交）
> 基线：`6c3fada feat(browser): 内置浏览器左上角改为关闭按钮`
> 验证环境：模拟器 `gxu35`（1080×2400 / 420dpi / Android 15），方法沿用 `AGENT.md`

---

## 0. 一句话结论

**不是"缺动画"，而是"缺动效体系"。**

现状盘点后可以看到：App 里已经有 10 处左右的手写动画（按压缩放、页签胶囊回弹、弹层入场、Toast、学期色块波浪入场……），
它们本身做得不错，但存在三个结构性问题：

1. **覆盖断层**：动画集中在"单个控件被点"这一层；真正影响"流畅感"的三类动效几乎全缺——
   **页面/内容切换**（tab 切换、周课表⇄总课表、筛选结果）、**列表/内容入场**（数据到了直接"啪"地出现）、
   **状态反馈**（加载中、空态、刷新成功没有过程）；
2. **参数各写各的**：时长从 80ms 到 1600ms 共 9 种、缓动 4 种、按压缩放 0.88/0.92/0.94/0.96/0.97/0.98 六种，
   同样的"按一下"在不同页面手感不同；
3. **关键交互是瞬切**：底部导航切页（内容瞬间替换）、总课表切换（visibility 瞬切）、
   详情弹窗（直接弹出）、成绩列表加载完成（瞬间铺满）——这些恰恰是用户感知"卡顿/生硬"的地方。

因此本方案的落点是：
**用一套动效令牌（4 档时长 / 3 条曲线 / 统一错峰）为骨架，把 30 个高价值交互点补齐过程动画。**

## 2. 动效原则（本方案所有效果都按这 5 条裁）

1. **动有理由**：每一个动画都对应一个用户动作或状态变化（"谁在动、为什么动、动去哪"）。
   不做无限循环的装饰动画（现有太阳呼吸保留，不新增）。
2. **快，并且先响应**：交互反馈 ≤ 120ms 开始；页面/列表入场 ≤ 320ms 完成；
   长列表错峰封顶（第 10 项后不再叠加延迟），绝不出现"为了看动画而等"。
3. **只动 transform**：统一使用 `translationX/Y`、`scaleX/Y`、`alpha`，
   不在这类动画里改 `layoutParams`/`padding`（会触发 requestLayout，列表里必掉帧）；
   高度变化只用于低频的展开/收起。
4. **同一屏只播一次**：入场动画只在"首次可见/数据首次落位"播放；
   滚动复用、转屏重建、返回页面不重复播，避免"每次回来都闪一下"。
5. **可关闭**：所有自定义动效统一走 `Motion.enabled()`，
   系统关闭动画（开发者选项动画缩放 = 0、无障碍"移除动画"）时直接落到终态，不阻塞功能。

## 3. 动效令牌（新增 `ui/motion/Motion.kt`）

### 3.1 时长

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `PRESS_DOWN` / `PRESS_UP` | 90 / 160ms | 按压反馈（抬起带一点回弹余韵） |
| `FAST` | 120ms | 图标旋转、小图标出现 |
| `SHORT` | 180ms | chip 脉冲、错误提示、小控件 pop |
| `MEDIUM` | 240ms | 页面内互斥内容切换、弹层遮罩 |
| `LONG` | 320ms | 底部弹层 / 对话框入场 |
| `ENTRANCE` | 260ms | 列表项、页面内容入场基准 |
| `STAGGER_STEP` | 34ms | 错峰步进（`min(index, 10) * 34ms`） |
| `COUNT_UP` | 560ms | 数字滚动 |

### 3.2 缓动

| 令牌 | 曲线 | 用途 |
| --- | --- | --- |
| `standard` | `PathInterpolator(0.2, 0, 0, 1)`（M3 standard） | 绝大多数位移/淡入 |
| `emphasizedDecelerate` | `PathInterpolator(0.05, 0.7, 0.1, 1)` | 大表面入场：对话框/弹层/展开面板 |
| `spring` | `OvershootInterpolator(1.15)` | 确认感动作：胶囊、回到本周、选中脉冲（幅度克制） |
| `accelerate` | `PathInterpolator(0.3, 0, 1, 1)` | 退出/淡出 |

### 3.3 公共封装（`Motion` object）

- `press(view, pressedScale)`：统一按压反馈（替换各页手写的 OnTouchListener）；
- `enter(view, delay, fromY, fromScale, alphaOnly)`：单元素入场（淡入 + 上浮归位）；
- `stagger(views, step)` / `staggerRecycler(rv)`：列表错峰入场（**封顶 10 项**）；
- `crossFade(from, to)`：同位置互斥内容切换（周课表⇄总课表、筛选结果）；
- `showPop(view, show)`：小控件出现/消失（回到本周 chip、空态图标）；
- `countUp(textView, target, format)`：数字滚动（绩点、均分、学分、门数）；
- `pulse(view)`：选中脉冲；
- `spinOnce(view)`：刷新图标转一圈；
- `resizeHeight(view, from, to)`：低频展开/收起高度动画；
- `enabled()`：系统动画开关；`resetScale(view)`：列表复用兜底。

## 5. 性能与可访问性约束

1. **动画只做 transform**：列表入场用 `alpha + translationY`；避免在滚动中做 `layout`。
2. **硬件层只在必要时开**：仅对大面积、短时动画设置 `layerType = LAYER_TYPE_HARDWARE`（如弹窗入场），
   结束后清掉；不做长期 `setLayerType`。
3. **动画取消与复用安全**：`Motion` 内所有方法先 `animate().cancel()`；
   列表项复用时 `Motion.resetScale`；数字滚动用弱引用表管理，防重复叠加。
4. **系统动画关闭时零成本**：`Motion.enabled()` 提前返回，直接落终态。
5. **不改变现有交互语义**：不加长点击延迟、不拦截点击、不改变返回栈行为；
   动画失败/被跳过时功能照常可用。
6. **淡入的 View 需先可见**：`enter()` 内部负责 `visibility` 与起始态，调用方不要在布局里再写 `alpha=0`
   （否则系统关动画时会永久透明）。

## 6. 验证方案

沿用 `AGENT.md` 的模拟器验证链路：

1. **数据准备**：模拟器注入一份演示课表（Room DB，学期开始日期对齐当前周），

3. **实机走查**（截图 + 录屏抽帧）：
   - 冷启动 Splash → 课表；
   - 三 tab 来回切换；
   - 周视图左右滑动 3 周；周课表 ⇄ 总课表；
   - 点课程格看详情弹窗；刷新；打开菜单拖周次滑杆；
   - 工具页 / 我的页 / 小组件中心 / 主题 / 外观 / 字体 / 时间表 / 关于 / 绑定页；
   - 成绩查询、考试安排、绩点页（有数据 + 空态两种）；
   - 深色模式抽查 3 页。
4. **性能基线**：`adb shell dumpsys gfxinfo <pkg> framestats` 截取上述交互，
   检查 95th percentile 帧耗时、jank 帧数；与改动前对比（基线截图/数据同时留档）。
5. **回归**：全页面冒烟 12 页 + 3 弹层，0 FATAL；`git diff` 不出现与动效无关的逻辑改动。

1. **B1 翻页中途边缘瞬态裁切**：页面内容放大到 1.04，滑动中内容左右各溢出页边界约 2%，

6. **模拟器环境**：连续长时间 `screenrecord`（>5 分钟）会让宿主 GPU 渲染断开、模拟器退出，

7. **无障碍**：所有动效统一走 `Motion.enabled()`，系统关闭动画时直接落终态；

### F5. 切换课表 / 刷新课表后，课表偶尔整体变灰

**现象**：用户反馈「切换课表或者刷新课表的时候偶尔会让课表变成灰色」。
表现为整页课程格子呈半透明/略微放大的灰洗状态，过一会儿（或再滑动一次）可能自行恢复。

**定位过程**：临时在 `ScheduleFragment` 里加了一个调试探针（每 800ms 采样一次
`viewPager.alpha` / `layoutOverview.alpha` / 当前页内容 `alpha` / 当前页课程卡片 alpha），
再用「翻周 + 周⇄总课表 + 菜单周次滑杆跳周 + 刷新 + 切 tab」压力操作复现。日志稳定出现：

```
W GRAYDIAG: suspicious#N: overview=true vpAlpha=0.0 ovAlpha=1.0 curContentAlpha=0.6 ...
```

即：处于总课表模式时，背后周课表当前页的内容仍停留在 **alpha=0.6、scale=1.04**（B1 翻页景深的
「相邻页」状态），连续 5 次采样（约 4s）都没有恢复。切回周课表后即以半透明状态显示 → 视觉上「课表变灰」。

**根因**：B1 翻页景深会给相邻页写入 `scale=1.04 / alpha=0.6 / 日期栏位移`。ViewPager2 的页 itemView
会被 RecyclerView 复用；当一页先作为「相邻页」被变换、随后被回收并**复用为当前页**时，如果这次切换
没有经过 `onPageScrolled`（典型路径：程序化瞬跳、切到总课表再切回来、刷新后 `notifyDataSetChanged` 重绑），
页面就继承了上一轮的半透明/放大状态。原复位逻辑只复位「当前页」，且 `findViewHolderForAdapterPosition`
找不到 holder 时直接放弃，覆盖不到这些路径。

**修复**（`WeekPagerAdapter` + `ScheduleFragment`）：

1. `WeekPagerAdapter` 新增 `resetPageDepthTransform(page)`，并在每个 ViewHolder 的 `bind()` 开头调用——
   **任何一次页面复用/重绑都从终态（scale=1 / alpha=1 / 日期栏无位移）开始**；
2. `ScheduleFragment.resetCurrentPageDepthTransform()` 从「只复位当前页」改为**复位所有已附着页**；
   RecyclerView 尚无子 View（程序化瞬跳时常见）时 `post` 到下一帧重试；
3. 从总课表切回周课表后，额外 `post` 一次兜底复位（总课表期间没有滚动事件，不会触发原有复位时机）。

**验证**：

- 同款压力操作（翻周 ×2 + 周⇄总课表 ×2 + 切 tab + 菜单滑杆跳周 + 刷新，共 8 轮）连续跑：
  修复前探针稳定复现「连续 4s+ `curContentAlpha=0.6`」；修复后 **0 次连续异常**（仅剩动画进行中的瞬时采样）；

## 附录 4：beta6 修复记录（v0.5.14beta6）

### F6. 点「查询」按钮时按钮闪烁

**现象**：用户反馈「点击查询按钮为什么会闪烁，是专门设计的吗」。成绩查询 / 考试安排页点「查询」后，
按钮在可见地一亮一暗地闪，看起来像故障。

**原因**：动效轮给 `PageStatusController` 加了「加载中查询按钮透明度呼吸」：
`ValueAnimator(1f ↔ 0.55f)`，单程 `Motion.SHORT = 180ms`、`REVERSE + INFINITE`。
一明一暗一个来回只有 360ms（≈2.8Hz），且幅度到 45%——录屏逐帧采样按钮区域亮度为
`84.6 ↔ 161.7` 反复横跳，肉眼读到的就是「闪烁」，而不是缓慢呼吸。**属于设计初衷未达预期，不是故障。**

**修复**（`PageStatusController` 一份实现，成绩查询 / 考试安排共用）：

- 把无限反向呼吸改为**一次性变淡**：加载开始 240ms 淡到固定 `alpha = 0.62` 并**保持**，
  加载结束 180ms 淡回 1；不再有循环，所以不会闪；

## 附录 5：beta7 功能补充（v0.5.14beta7）

### F7. 新版本提醒在底部导航「我的」页签也显示红点

**需求**：此前检测到新版本时，只有「我的 → 关于应用」行右侧有红点；用户如果没进「我的」页就看不到提醒。
现在要求底部导航的「我的」页签也带红点。

**实现**：

- `PillBottomNavView`：给「我的」页签图标右上角加 9dp 红点（复用 `res/drawable/dot_update_hint.xml`，
  与「关于应用」行同款），新增 `setUpdateHint(show)`：状态变化时淡入 + 0.6→1 缩放（`Motion.SHORT`，无循环闪烁），
  熄灭时直接隐藏；点亮时把该页签的无障碍描述同步为「我的，有新版本可更新」。
- 红点语义与「关于应用」行**完全同源**（`SettingsManager.hasNewUpdateHint()`：最近检查到的最新版本 >
  当前安装版本），因此安装新版本后两处一起熄灭；「跳过此版本」不影响红点（与既有语义一致）。
- `UpdateService.hintChangedListener` 由「单回调槽位」改为多监听者 API
  （`addHintChangedListener` / `removeHintChangedListener`，内部 `CopyOnWriteArrayList`）：
  MainActivity（底部导航红点）、ProfileFragment（关于行红点）、AboutActivity（检查更新行红点）
  可同时注册、互相不覆盖。
- `MainActivity`：onCreate 先按本地记录回灌红点，再启动每日静默检查；onStart 注册监听并刷新、onStop 注销；
  onResume 兜底同步一次（后台去装新版本等场景）。

**验证**（模拟器，先清掉「今日已检查」记录触发静默检查）：

  「我的，有新版本可更新」；关闭对话框后红点保留；
- 「我的」页签未选中 / 选中、浅色 / 深色四种状态均正常（截图 `01_底部导航我的页签红点_三态.png`）；
